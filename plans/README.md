## Findings considered and rejected (so they are not re-audited)

- **Attack / personal-attack stacking math** (`engine.ts:472`, tested at
  `engine.test.ts:249-320`): correct and matches `RULES.md` §4 + the tests'
  documented decisions (e.g. personal-attack adds turns: 2→4). Not a bug.
- **Streaking-kitten shield** (`engine.ts:450`): `streaking > exploding` strict
  comparison correctly implements "hold more streaking kittens than exploding
  kittens" (`RULES.md` §6). Not a bug.
- **Card conservation / elimination / `returnHeldPhaseCards`** (`engine.ts:387-425`):
  verified by `checkInvariants` + the 400-game simulation sweep + chaos playout.
  Solid.
- **`int(state, 0)` / division-by-zero in RNG**: every `int(...)` call site is
  guarded so the bound is ≥1; and `int` would return 0 (not NaN) anyway. Not a bug.
- **`reduce` exhaustiveness with `timeout`/`concede` handled before the match**
  (`engine.ts:752-768`): TypeScript narrows the union before `.exhaustive()`, so
  it is sound and compiles. Not a bug.
- **Per-game (not global) card ids** (`engine.ts:110`, `card-${counter}`): ids only
  need per-game uniqueness; the redacted snapshot is per-game. By design.
- **Schemas defined but not parsed inside the engine** (`model.ts`): "parse at the
  boundary" (CONVENTIONS rule 2) is the server's job per ADR 0001; the engine
  trusts typed inputs by design. Considered as a direction item (a `parseCommand`
  boundary helper) rather than a defect.

## Direction findings (options for the maintainer, not scheduled here)

These were surfaced in the audit as forward-looking options; no plans were
written for them (they need a design decision first). Recorded so they are not lost:

- **Event audience tagging.** Domain `Event`s are advisory cues the server
  distributes, but only `future-revealed` carries an audience (`to`). `card-drawn`
  (`model.ts:193`) is inherently private to the drawer yet untagged, so the server
  must hardcode which events are private — a latent leak risk for the server
  milestone. Consider an explicit audience marker. Grounded in ADR 0002.
- **A `parseCommand` / `parseConfig` boundary helper exported from `engine`.**
  The schemas exist (`CommandSchema`, `GameConfigSchema`) but nothing in the
  packages parses with them; a thin exported helper gives the server one canonical
  "parse at the boundary" entry (CONVENTIONS rule 2). Low effort, high payoff when
  the server is built.
